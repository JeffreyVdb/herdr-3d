# Native subagents on the office summary board

Ticket: [#170](https://github.com/JeffreyVdb/herdr-3d/issues/170).

## Problem and outcome

The office summary board shows agents, orchestrators, and their freelancers, but hides the native Claude Code/Codex subagents doing delegated work inside those sessions. Show those children beneath the worker that owns them, with live status and a clickable link that opens **that child's transcript directly**, including while it is running.

Example: `orchestrator → freelancer → native subagent`. Ordinary agents and orchestrators can also have native children directly. Support recursive children where the provider exposes deeper delegation. Native subagents are conversation entities within a worker, not new Herdr panes, hired freelancers, or physical desks.

## Research conclusion — 2026-10-07

**Both providers are feasible. Claude SDK migration is not required.** Retain Claude's native CLI and JSONL transcripts; add child discovery/live observation, optionally strengthened by documented lifecycle hooks. For Codex, extend the shared app-server adapter already implemented by #154–#158. Preserve JSONL history/fallback for legacy sessions rather than requiring a complete transcript rewrite.

Web research used **Alterlab MCP** and primary documentation. Code findings below refer to current `main`, commit `d460361b1fc8765507aad77a26f6de2266d66922`, not the older local checkout. Installed Codex **0.160.1** schemas, Claude Code **2.1.292**, and real local transcript metadata were inspected read-only. The subagent-specific live runtime checks below remain implementation acceptance work; this investigation did not execute them.

| Provider | Discovery and identity | Live observation | Transcript |
| --- | --- | --- | --- |
| Claude Code | Parent session plus child `agentId`; child files already exist and are partly supported | Tail child JSONL; lifecycle hooks improve early identity and start/stop evidence | Reuse existing child parser/page/image support, add direct selection and live watches |
| Codex shared server | Child `thread.id`, `parentThreadId`, source metadata; explicit descendant discovery | Extend existing adapter with child routing/subscriptions and recovery | Read child thread history or its existing rollout; add live child transcript target |

### Claude: why the current JSONL approach can work

Claude persists child conversations separately at `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl`. Reading only the main JSONL misses the child's intermediate conversation. Transcript persistence and resume are supported, but configured cleanup can remove old history. Existing Herdr 3D code already recognizes `Agent` and legacy `Task` calls and can load a child transcript after learning its ID. [Claude subagent transcripts and resume](https://code.claude.com/docs/en/sub-agents#resume-subagents).

The current parser learns `agentId` from `toolUseResult`. This can be too late for opening a synchronous child while it is working. File discovery can expose child identity earlier, but file presence/mtime is not authoritative lifecycle evidence and concurrent children must not be paired by timestamp guesses.

Documented `SubagentStart` supplies `session_id`, main `transcript_path`, `agent_id` and `agent_type`; `SubagentStop` additionally supplies `agent_transcript_path`. **Start has no documented parent-agent ID or spawn `tool_use_id`.** Start also fires on resume and in-process teammate messages, so it does not always mean a new child. Stop means response completion and can be blocked by another hook, causing continued work; internal suggestion and `/btw` agents can also emit it. The integration should be observational, preserve existing hooks, and reconcile background work, continuation, crashes and session changes. Root completion does not prove child completion. [Start inputs](https://code.claude.com/docs/en/hooks#subagentstart-input), [Stop inputs and continuation](https://code.claude.com/docs/en/hooks#subagentstop), [root background tasks](https://code.claude.com/docs/en/hooks#stop).

Local metadata sampling found 161 child JSONLs; recent child records carry `agentId`, `sessionId` and `isSidechain`. Parent structured `toolUseResult` records expose `agentId` with `async_launched` or `forked` status; associated tool-result blocks expose `tool_use_id`. These are implementation observations, not a public versioned JSONL schema: add tolerant parsers and fixtures. Pair by explicit IDs, not concurrent launch order. Agent-team teammates and internal helpers need classification rather than blindly becoming disposable subagent rows. [Teammate lifecycle](https://code.claude.com/docs/en/hooks#teammateidle).

When the SDK drives a session, child messages carry `parent_tool_use_id`, providing supported live correlation. Its read-only `listSessions`/`getSessionMessages` utilities are separate from migrating worker execution; fetched docs do not establish child-enumeration helpers. Retaining the CLI is sufficient here. The current SDK documentation permits nested subagents, but immediate-parent correlation in CLI hook/JSONL evidence still needs verification. [SDK invocation detection](https://code.claude.com/docs/en/agent-sdk/subagents#detect-subagent-invocation), [read-only session utilities](https://code.claude.com/docs/en/agent-sdk/sessions#session-storage), [nested children](https://code.claude.com/docs/en/agent-sdk/subagents#cap-subagent-depth-concurrency-and-spend).

### Codex: extend the existing server connection

The official app-server protocol offers observational `thread/read`, `thread/list`, runtime status notifications, and turn/item streams. `thread/read` does not load or resume the thread. Experimental `parentThreadId`/`ancestorThreadId` list filters support descendant recovery. **Omitted or empty `sourceKinds` defaults to interactive sources and excludes subagents**: request relevant child sources explicitly. [Official app-server documentation](https://developers.openai.com/codex/app-server).

Installed 0.160.1 generated schemas confirm:

- `Thread`: `id`, `sessionId`, `parentThreadId`, `source`, `agentNickname`, `agentRole`, `status`, `ephemeral`. **Use `thread.id` as child identity; `sessionId` is shared across the tree.** `forkedFromId` describes a history fork, not the parent relationship.
- `collabAgentToolCall`: sender/receiver thread IDs, tool-call status and `agentsStates`. Finishing `spawnAgent` or `wait` is not itself proof that the child finished.
- `subAgentActivity`: child thread ID/path and activity kind `started`, `interacted`, `interrupted`, `completed`. Support this newer representation as well as collaboration-call items; matching only a `spawn_agent` function name is insufficient.
- Experimental parent/ancestor filters appear when generating bindings with `--experimental`; the client must negotiate experimental capability and handle unsupported versions.

Read-only local scans also confirmed real 0.160.1 child rollout metadata under `source.subagent.thread_spawn`, including `parent_thread_id` and depth, plus persisted `event_msg/item_completed` entries for `SubAgentActivity` and `CollabAgentToolCall`. Persisted names use snake_case/PascalCase, whereas the app-server representation uses camelCase. Normalize each representation explicitly. This makes legacy JSONL discovery feasible, but does not establish complete live or crash-safe lifecycle reporting.

Connect to the server that **owns the worker's running conversation**. An unrelated server reading the same history does not provide authoritative live status for that process. Shared ownership/launch/resume is already implemented; reuse it. Verify whether parent subscriptions cover child events and explicitly join required loaded children when needed. Read completed/unloaded children observationally rather than loading every historical child. Handle ephemeral children separately from the current root-worker watcher, which rejects ephemeral threads. [Existing shared-server epic](https://github.com/JeffreyVdb/herdr-3d/issues/153), [implemented connection research](https://github.com/JeffreyVdb/herdr-3d/blob/d460361b1fc8765507aad77a26f6de2266d66922/docs/research/codex-shared-tui.md).

## What is missing in current Herdr 3D

1. **Child registry and lifecycle independent of an open transcript.** Claude usage already discovers/tails child files every 10 seconds, but its transcript callback publishes main lines only. Expose this discovery as reusable child events. Codex's watcher decodes no parent/source/nickname metadata, and the server notification handler filters out non-root thread IDs. Add a child observer without changing root async-question semantics. [Claude discovery seam](https://github.com/JeffreyVdb/herdr-3d/blob/d460361b1fc8765507aad77a26f6de2266d66922/internal/usage/session.go#L41), [Codex thread model](https://github.com/JeffreyVdb/herdr-3d/blob/d460361b1fc8765507aad77a26f6de2266d66922/internal/codexapp/watch.go#L93), [root event filter](https://github.com/JeffreyVdb/herdr-3d/blob/d460361b1fc8765507aad77a26f6de2266d66922/internal/server/codexquestions.go#L124).
2. **Provider-neutral child transcript routing and live watches.** Current child page/item lookup is Claude-only, reads files on request, and caches just four child logs per parent watch. The renderer offers nested snapshots/Reload, not a standalone live child view. Codex's structured item parser handles MCP items but has no native child mapping. [Current child resolver](https://github.com/JeffreyVdb/herdr-3d/blob/d460361b1fc8765507aad77a26f6de2266d66922/internal/server/transcript.go#L687), [transcript protocol](https://github.com/JeffreyVdb/herdr-3d/blob/d460361b1fc8765507aad77a26f6de2266d66922/internal/proto/transcript.go#L171), [Codex parser](https://github.com/JeffreyVdb/herdr-3d/blob/d460361b1fc8765507aad77a26f6de2266d66922/internal/transcript/codex.go).
3. **Recursive board rows.** `OverviewNode.children` contains worker rows and visible depth is `0 | 1`. Both the HTML board and wall canvas need native child row types and arbitrary tree traversal. Update collapse, keyboard navigation, counts, ordering and overflow. [Overview model](https://github.com/JeffreyVdb/herdr-3d/blob/d460361b1fc8765507aad77a26f6de2266d66922/game/src/world/overview.ts#L82), [visible depths](https://github.com/JeffreyVdb/herdr-3d/blob/d460361b1fc8765507aad77a26f6de2266d66922/game/src/world/overview.ts#L252), [wall renderer](https://github.com/JeffreyVdb/herdr-3d/blob/d460361b1fc8765507aad77a26f6de2266d66922/game/src/render/overviewScreen.ts).
4. **Direct child navigation.** Board activation passes only a worker ID to `goToWorker`. Add a transcript target with worker ID, parent session generation, provider and child ID. Seat at the owning worker and immediately select the child conversation, with a breadcrumb/back-to-parent. Generalize watch/page/item/image/cache keys and reject stale replies after session replacement. [Board activation](https://github.com/JeffreyVdb/herdr-3d/blob/d460361b1fc8765507aad77a26f6de2266d66922/game/src/ui/overview.ts#L571), [worker navigation](https://github.com/JeffreyVdb/herdr-3d/blob/d460361b1fc8765507aad77a26f6de2266d66922/game/src/app.ts#L3252).

## Implementation plan

- [ ] **Define child state and protocol.** Provider-scoped stable ID, root worker/session generation, parent child ID where known, name/type/description, task state, timestamps, evidence source, transcript availability. Add snapshot/upsert/remove events and reconstruction after restart. Keep task completion, idle/reusable, shutdown, disconnected/unknown distinct. Keep provisional dispatch IDs stable when reconciled to native IDs. Represent unknown linkage explicitly; do not fabricate an immediate parent.
- [ ] **Implement Claude discovery and observation.** Reuse existing child directory discovery, extend early identity/lifecycle capture, tail child logs, and integrate nonblocking lifecycle hooks where available. Preserve user hook configuration and allow degraded JSONL-only observation. Use actual/configured transcript roots, not only the default home. Handle incomplete lines, create/replace, compaction and cleanup. Verify exact hook/tool correlation fields on supported versions before assigning descriptions to concurrent children. File absence should produce pending/unavailable, not a broken or incorrectly attributed transcript.
- [ ] **Implement Codex child adapter and fallback.** Extend existing `internal/codexapp` metadata/routing, recover descendants with explicit source filtering, subscribe to necessary live children, reconcile activity/status, and unsubscribe only the bridge's subscriptions. Preserve native terminal approvals and existing async-question handling. For legacy workers, separately index child rollouts by parent metadata; keep children excluded from root-session recovery. Handle both nested and top-level parent metadata across supported versions.
- [ ] **Add live child transcript targets.** Extend page/item/watch/push/image routing for both providers, including older pages and completed-child history. Preserve cursor/sequence isolation, image authorization and late-ack protection. Account for inherited Codex history so copied parent context is not labeled as new child activity. Bound child caches/watches while retaining discoverable completed history.
- [ ] **Render and navigate the hierarchy.** Update shared overview model, HTML board and office wall screen. Rows show provider/name or task, lifecycle, elapsed time where meaningful, and transcript availability. Child selection opens its live transcript directly; parent navigation remains available. Preserve existing worker totals, and avoid double-counting child tokens already included in parent usage.
- [ ] **Run provider fixtures and real-terminal smoke checks.** Record supported Claude/Codex versions, observed identity timing, event delivery scope, and restart recovery. Use the existing mock-inference/shared-TUI fixture for Codex rather than assuming parent subscription behavior.

## Acceptance criteria

- A running Claude foreground or background child appears under its owner **before it reports back**, with a usable child transcript when available. At least two concurrent children remain correctly identified. Completion, resume, Stop-hook continuation, parent-idle/child-running and interruption reconcile without duplicate rows. Unknown immediate parentage remains explicitly unresolved until validated.
- Codex spawn/interact/follow-up/wait/interrupt/close transitions resolve to the correct child thread. Child work and tool-call status are never conflated. Loaded, unloaded and ephemeral cases have defined behavior; historical reads do not start a turn or override worker configuration.
- Children appear under ordinary agents, orchestrators and freelancers on both board surfaces. Provider-exposed deeper children are supported. Keyboard selection, expand/collapse and long trees remain usable.
- Clicking an active or completed child opens its own conversation, streams available new entries, supports history/images and offers return to parent. Missing or not-yet-created logs have an explicit state.
- Reconnect/restart recovers the graph and transcript identity. Session replacement, two roots sharing a directory, and reused/resumed children cannot attach to the wrong worker. Quiet logs never alone imply completion; server/process loss invalidates stale running claims.
- The board updates even when no transcript is open. Observing children preserves native terminal operation, approvals, prompts and existing Codex async-question behavior.
