# Verification: server model

Verified 2026-09-28 against Herdr 0.9.0 on both hosts and the current Herdr 0.9.1 documentation (released 2026-09-16). Original: [server-model.md](server-model.md).

## TL;DR

**Verdict: CORRECTIONS.** A server side bridge remains the sound choice for a single Mac game connection and durable game data. The main flaw is the proposed "open in real terminal" path: attached Herdr clients can view different workspaces, so calling `workspace.focus` or `agent.focus` through the socket cannot be relied on to navigate an already attached Mac client. Those focus calls can also mark an agent's `done` state as seen. The document also applies a 0.9.1 observer stall timeout to installed 0.9.0, includes an unnecessary `agent.list` during bootstrap, and presents an unsupported bridge resource estimate as measured fact. The `session.start` sketch needs an actual headless launch and supervision design before implementation. A user service cannot use `After=tailscaled.service` to order itself against this host's system service.

## Omissions and impact

- **Client-specific terminal navigation:** Define the Mac-side behavior for already attached windows. A server API focus request is not a verified client navigation command. A new `herdr --remote` window can open the session, but selecting a particular pane still needs a user action or a supported targeted mechanism. Focus side effects on `done` should be considered before using the API.
- **Stopped session startup:** Specify who owns the headless Herdr server process and how it is kept alive. `systemd --user` for the bridge does not automatically supervise servers launched by the bridge.
- **Service readiness:** The user manager cannot order the bridge after the system manager's `tailscaled.service`; make bind/WhoIs setup retry until Tailscale is ready.
- **Terminal stream backpressure:** The 0.9.1 observer timeout is not a substitute for bridge-side bounded queues, per-viewer cancellation, and re-opening on stream EOF, particularly while deployed Herdr remains 0.9.0.
- **Identity lifecycle:** StableID and IP observations are current inventory, not constants. Resolve WhoIs on new connections and expose a clear denial if the Mac is re-enrolled under a new node ID.
- **Workspaces after restore:** A workspace can return while its original process is gone; native agent resume depends on integration state. Treat workspace existence separately from agent liveness.

The recommended bridge architecture, narrow command API, WhoIs authorization, and SQLite storage remain valid. Correct the terminal-open promise and headless session launch before using the document as an implementation specification.
