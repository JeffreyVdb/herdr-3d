# Verification: herdr internals and API surface

Verified 2026-09-28 against the installed Linux and Mac binaries, the live `herdr-3d` session, the local persisted state, and upstream tagged documentation/source. The source tag dates are [v0.9.0, 2026-09-07](https://github.com/herdrdev/herdr/releases/tag/v0.9.0) and [v0.9.1, 2026-09-16](https://github.com/herdrdev/herdr/releases/tag/v0.9.1). No existing session, pane, workspace, or agent was changed. The original [research document](herdr.md) was not edited.

## TL;DR verdict

**CORRECTIONS.** The server-side bridge remains the right general architecture. Its cold-start plan needs a change: starting a stopped Herdr server restores layout and a pending agent-resume plan, but native agents do not resume until a Herdr client attaches and supplies terminal geometry. The proposed UUID workspace token is ephemeral and cannot detect a recycled workspace ID after a cold restart if the bridge missed events. The event stream is real, but unfiltered status subscriptions do not send an initial status, the 100 ms loop is not a latency ceiling, and `workspace.closed` does not always include a final snapshot. The draft also shows `agent read` as JSON output although that CLI command prints text; raw `pane.read` socket calls return JSON.

## Omissions and impact on recommendation

1. **Cold-start activation:** A server-side bridge can discover and read a stopped session after starting its server, but must not show restored agents as running until a Herdr client has attached and provided geometry. Define that activation path before promising a game-controlled session start. If no client is available, show the floor as restored but awaiting attach.
2. **Durable identity:** The bridge store should record generation/creation information when it sees a workspace created or hired. After downtime or cold restart, a `wN` with no trustworthy durable identity must be reconciled before inheriting a previous avatar, role, or parent link. Reapplying an old UUID token solely by ID would hide a collision.
3. **Event recovery:** Subscribe, take a snapshot, apply buffered events, and repeat the snapshot after reconnect. Maintain the last known workspace state for closure events. Treat status events as changes, with the snapshot supplying initial status.
4. **Screen stream recovery:** Reopen an observer after EOF or stall and request a fresh full frame. Give the game a bounded queue so a slow Mac renderer cannot retain unbounded frames.
5. **CLI/API distinction:** Use raw socket calls when the bridge needs typed JSON; Herdr's human-facing `agent read`/`pane read` CLI output is text.

With these changes, one server-side bridge per host that watches all session sockets, owns building/worker metadata, and exposes one authenticated game API remains justified. No evidence calls for direct Mac-to-every-socket access or for replacing Herdr's event API with broad polling.
