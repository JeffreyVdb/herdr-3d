# Verification: write-code orchestrator flow

Verified 2026-09-28 against the installed skill and CLIs, live Herdr state (read-only), and first-party documentation. The local Herdr binary is 0.9.0; the Herdr documentation site currently advertises 0.9.1. Undated web pages below were accessed on 2026-09-28.

## TL;DR verdict

**CORRECTIONS.** The workflow, watcher, role labels, review limit, and hire flag shapes are substantially accurate. The recommended metadata convention cannot carry the proposed full `h3d_report`, `h3d_brief`, or `h3d_run` paths: Herdr caps each token value at 80 characters, while representative paths here are 129–130 characters. Use a short run ID and relative report keys, then resolve them through a server-side registry. The game can still ship an initial label/status-based display. The draft's live parent and report tracking recommendation requires this correction before implementation.

## Omissions and recommendation impact

1. **Use a short stable key.** The bridge can derive the registry path from `h3d_run_id` under one configured server-side directory. Store full brief/report paths in `run.json`, and put only relative report names or IDs in workspace tokens. A run registry should be created before the first worker and updated atomically, so a new bridge process can recover the mapping after Herdr loses tokens on restart.
2. **Subscribe for live updates.** [Herdr Socket API](https://herdr.dev/docs/socket-api/) says `session.snapshot` is a one-time bootstrap snapshot and `workspace.metadata_updated` is an event available to API subscribers (accessed 2026-09-28). The bridge needs an event subscription or polling; a single `herdr api snapshot` cannot drive animations continuously.
3. **Keep the first version heuristic.** The role regex and agent status are available now and accurately support a basic floor view. Parent matching in a multi-ORCH session must be shown as inferred, and report/phase animations must wait for the corrected registry convention.
4. **Use unambiguous skill invocation and fixed model IDs.** `/mattpocock-skills:implement` is safer than `/implement` if a future install introduces a collision. The draft's full Claude/Codex model slugs and model-specific effort menu remain sound. Treat “cheaper research model” as a suggestion from the skill, not a verified cost or performance ranking.
5. **Retain the user's review boundary.** A historical `r4` workspace exists, but the current skill caps review at three passes. The game should show any fourth pass as an explicit exception; the historical evidence alone does not prove authorization.
