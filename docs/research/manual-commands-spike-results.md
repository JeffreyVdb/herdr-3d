# Manual commands spike results

The integrated bridge runs a reviewed manual command in an unfocused, labelled sibling tab, without changing the worker's pane. A private Herdr session and bridge exercised manual entry, terminal input, detach, distinct process records, fake askpass retries and cancellation, and scoped fake Tailscale Serve cleanup. The browser fixture suite also exercises command cards and their foreground variants. The private-session evidence from the integration run is under `int-r1/` in the run directory `20261026-2123-mancmd`; `ux-run.sh` there starts a private bridge, proxy and game for another inspection.

The private bridge was restarted with a process running: the record returned to `running` with the same PID and start ticks. Floor sleep stopped it with a sleep note; after wake the restored manual tabs were closed and the process was not relaunched. With isolated XDG runtime directories, the first wake could not find the user systemd bus. A local `systemd-run` wrapper connected to the user's bus and explicitly passed the isolated XDG settings to the throwaway session; the retry succeeded. This is a private-test setup detail, not evidence that ordinary wake requires a product change.

A detached, HUP-ignoring child survived the initial Stop and was reported as `cleanup: needed`. Send-home refused while the child could not be verified stopped; a second Stop removed the recorded identity and send-home succeeded. A separate fake Serve effect stayed visible as cleanup needed after its worker was gone. The later core fix retains authenticated process-group identities rather than trusting a stale numeric group; a fresh private-session detached-child Stop and retry passed after that merge.

The fake sudo fixture honoured `-A` and invoked the private askpass helper. A wrong synthetic marker caused a new request at attempt 2, the right marker let the command run, cancellation ended another command, and a late answer was stale. Scans of the bridge log, database and WAL, audit rows, session state and process command lines and environments found no marker. These are synthetic tests, not a PAM or real-password validation. The fake Tailscale fixture refused a pre-existing endpoint, recorded a clean start as active, and recorded `serve --bg --https=8443 off` after the cleanup password dialog; the effect then became removed.

The real-bridge browser trial used manual entry. The requested end-to-end demonstration of a command request produced by a real agent reply through the classifier was not completed in that trial; classifier fixtures and the browser fixture suite cover the respective halves, but do not prove that combined path. No paid model call was made.

## Cleanup contract

Foreground processes are owned by their launcher identity (PID plus start ticks), and Stop signals their verified process group with bounded escalation. Closing the terminal view only detaches. Detached descendants can escape the group; the bridge reports known survivors as cleanup needed and a later explicit Stop retries only recorded, re-identified processes. It does not promise universal process-tree containment. Background Tailscale Serve is an external effect: its endpoint is checked before launch and remains cleanup needed until the scoped `off` command exits successfully. Arbitrary external effects are unmanaged.

The operator still needs to run the live sudo/PAM and live Tailscale checklist in the issue, including cached authentication, foreground Serve shutdown and preservation of an unrelated endpoint. No upstream Herdr/API change was identified as necessary for the supported input and labelled-tab paths; stronger containment for arbitrary detached or privileged descendants would need further investigation rather than being inferred from this spike.
