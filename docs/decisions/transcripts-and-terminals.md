# Transcripts and terminals decisions

## 2026-09-30 — #56 (M16 phase 2): images in the transcript view, the Images tab and the desk prints

| # | Question | Decision |
|---|---|---|
| 1 | Where the bytes live | **Not in items.** An item carries an `ImageRef` (sha256 of the bytes, sniffed mime, size, `origin` input/agent, `kind` generated/viewed, the item it is in). Bytes are served by `transcript.image` for a hash **this connection was sent**, so a client cannot ask for what it was not shown and never names a path. Inline images are decoded and hashed once per transcript line (remembered by line offset), filed in a 64 MiB LRU (`imgcache`) plus an optional 0600/0700 disk cache, and read again from their line when neither has them: the cache can be small and lose things. |
| 2 | Path images | Only under an allowlist: Drop Zone's data, `~/.codex/generated_images`, the worker's cwd and the exact file of a Codex `view_image`. The check is lexical first (a path outside every root is refused **before any file system call**, so an outside file is not even looked at), then again after `EvalSymlinks`, then regular file, image bytes, <= 25 MB. The read itself does not reuse the checked path: it walks down from `/` along the real path one component at a time with `O_NOFOLLOW` (`O_PATH` for the directories on Linux, so a pass-through-only directory still works; any directory swapped for a link after the check, below the root, the root itself or one above it, is refused), opens the file non-blocking (a FIFO swapped in cannot hold the bridge) and checks the opened descriptor. The cost is that a path reached through some other symlink than the root's own spelling is refused; that is the safe side. |
| 3 | Thumbnails | Cut on demand (pure Go, CatmullRom, at most 2 at once), cached with the images; JPEG stays JPEG, the rest is PNG. Full images are capped at 12 MiB of base64 (`too_large`; the view says so and keeps the thumbnail). |
| 4 | Images tab data | `transcript.images` lists the whole session from the offset index (an item flagged as having images is read back once); it is not the watch's 200-item window. It is paged with a cursor (`before`, `limit`, `has_more`): the client follows it to the end however many pages that takes, nothing is cut off; a cursor that does not move on (one given before, or none with `has_more`) fails the list, which the tab shows, instead of passing a part for the whole. Hash dedupe and the count badge are the game's. |
| 5 | Grouping rule in the conversation | Consecutive **image-only** items (a `user` or `assistant` item with images and no text) of the **same role** share one strip. A text part, any other visible row (tool, subagent, thinking, compaction, notice) and a change of role break the run; rows the view hides do not (unless "show system" shows them). Within one message or tool row all images are one strip, text between images makes another. Grouping across tool rows (a run of `Read`s) stays out: a tool row breaks a run. Since #70 a tool row's strip shows with the row collapsed (and, bare, with tool calls hidden); it is still that row's own strip and still breaks a run. |
| 6 | The plan-limits plate over the reading overlay | The overlay is a screen like the M3 panels: the plate steps out into its edge tab (Shift+L peeks) instead of hanging over the overlay's header. |
| 7 | Desk prints | A desk's front strip, IN tray (white-bordered prints) on the worker's left, OUT tray (coloured) on the right, at most 5 + 5. Loaded only for the two nearest visible desks and disposed when they drop out (textures, bitmaps, object URLs); their data is a transcript watch with a limit of 1 plus `transcript.images`. |

## 2026-10-01 — a laptop of a split pane is fullscreen (#74)

| # | Question | Decision |
|---|---|---|
| 1 | What showed a split pane's laptop narrow? | Not the renderer: `terminal.watch` takes the pane's own size from `session.snapshot` and the observer does not reflow, so a pane in a 60-column split is 60 columns (the agent renders at that width). A single-pane worker is the tab's full width. |
| 2 | Ask or always? | **Always fullscreen**, decided after the research below: the game sends `fullscreen: true` by default and the bridge zooms the pane's tab with herdr's pane zoom (`pane.zoom` / `herdr pane zoom <pane> --on\|--off`) while a laptop sits at it, and puts it back on standing up. The issue's idea 4 had "a seat bar button, never automatic"; the seat bar keeps a visible, undoable fullscreen chip (and the preference `h3d.term.fullscreen`), but nothing waits to be asked. |
| 3 | What herdr 0.9.0 does (verified in throwaway sessions, report `ground-zoom-report.md` of the run) | Zoom is a per-**tab** boolean; the visible zoomed pane is the tab's focused one. `--on` is idempotent but always focuses the target (it moves the human's TUI focus); `--off` is idempotent. Splitting a pane or closing a sibling clears the zoom. A zoom survives workspace and tab switches, client detach and a server restart. `session.snapshot` keeps reporting the **split** rectangles of a zoomed tab; its layout has `zoomed`, `focused_pane_id` and the tab's `area`, which the bridge's `PaneSize` now reads. |
| 4 | The size of a zoomed pane | The tab's `area`. With a TUI attached the real terminal is about 3 columns and 2 rows smaller (area 114 × 49 gave 111 × 47: borders, scrollbar); the observer pads the difference and observer frames carry the requested size, not the real one, so there is nothing to correct the guess with. Padding is kept over subtracting: a guess that is too small would cut off the bottom rows, where the prompt is. |
| 5 | The headless limit | With **no client attached** a zoom resizes no terminal (open upstream issue herdrdev/herdr#1709): the bridge can flip the flag but cannot make the PTY wider. The snapshot has no field for the real columns either. The bridge calls it `headless` when the tab's area is herdr's headless 120 × 40 (a TUI window is never exactly that: the sidebar takes columns) and the seat bar says "Fullscreen unavailable" instead of promising a wide screen. The zoom is still applied: a TUI attaching later finds it. |
| 6 | Who owns a zoom? | The bridge remembers per (session, tab) that **it** zoomed the tab, counted by the fullscreen watches of that tab over all connections. It puts the tab back when the last one ends (unwatch, a re-watch without fullscreen, a dropped connection, a worker removed or its pane changed, the bridge stopping) and the tab is still zoomed. A tab that was already zoomed before the watch, or that the human unzoomed since, is never touched, and nothing is called for an asleep session. A re-watch keeps the zoom. `terminal.zoom off` is the player's explicit act and does unzoom a tab the human zoomed. Review rules (round 2): a watch counts as an owner only while it wants the tab fullscreen (`true`, or `terminal.zoom on`; a follower or one that turned it off is not counted, so it cannot keep the last real owner from restoring); the pane's state is read inside the write lock, before deciding to zoom, and again before a restore, which also checks the pane is still in the tab the bridge zoomed (a pane the human moved is left alone); a `terminal.zoom` is bound to its watch and does nothing once the watch ended. |
| 7 | Why never re-apply? | A human who unzooms or moves the focus while a laptop sits there meant it, and a bridge that zooms again would fight them every poll. The bridge reports the change (`terminal.state`, the zoom state and the new size, polled from the snapshot every 2 s while a watch that sent `fullscreen` lives, and the observer follows the new size) and the seat bar offers the re-apply. That includes a re-watch: the game re-watches for a new fps (reading the transcript) or after a frame gap, and such a watch takes over the decision of the one it replaces instead of zooming again, so only `terminal.zoom on` re-applies. |
| 7b | `fullscreen` is a tri-state | `terminal.watch.fullscreen` is a `*bool`: absent (an old client: no zoom, no polling, no `terminal.state`, exactly as before #74), `true` (zoom and own it) and `false` (no zoom, no ownership, but the watch follows the tab so the chip and the size stay true when the human zooms, moves the focus or resizes). The game sends `false` for the seated watch when the preference is off, and nothing for the ambient laptops. `terminal.zoom` stays the explicit act: it reports a herdr failure as `input_failed` (only the zoom at watch time is fail-open). |
| 8 | Why not move the pane to its own tab instead? | `pane move` changes the pane's id across workspaces and refuses a zoomed tab; it rearranges what the human built and cannot be undone by standing up. Zoom is a flag that is put back with the same command. Resizing a split (`pane resize`) steals the siblings' space. |
| 9 | Stop the splits at the source | The orchestrator's run prompt (`RunPrompt`, also what `run.prepare` returns) has one fixed line: every agent it hires goes in its own workspace or tab, never in a split pane of its own tab or another agent's tab, because a laptop shows a pane at its own size (a fullscreen terminal is wanted). It is there for every ticket kind. |
| 10 | The write path | Two new shapes in `controlShapes` (`herdr --session <s> pane zoom <pane> --on` and `--off`, nothing else: never `--toggle`, never without a mode), each write its own audit row `pane.zoom` (`session`, `pane`, `mode`, `why`), apart from the command's row. |
| 11 | When the zoom does not help | If the screen is still much narrower than the monitor (zoom off, or headless), the terminal's A+ / A− default fits the width instead of the height only (the letterbox is at least not tiny text), and the seat bar says why: "Split pane 60×40". *(Superseded in part by #175, row 1: 100% is the whole grid, letterboxed; the seat bar's chip stays.)* |

## 2026-10-21 — the seated terminal never enlarges a narrow pane by itself (#175)

| # | Question | Decision |
|---|---|---|
| 1 | What is 100%? | **The whole grid**, whatever the pane's width: `viewport` at 100% is `cellGrid`'s fit, its cells kept to `CELL_ASPECT` (letters never stretched wide), centred, with bars at the sides of a narrow pane. The cells grow only by the user's own zoom: A+ / A−, Ctrl + wheel and Ctrl + = / + / − / 0 (70–200%, above 100% the bottom-left of the pane, following the cursor). ## 2026-10-21 — #176 part 1: the full-window seated workspace, an opened xterm 6 and herdr's terminal controller

Sitting at a worker opens an in-app workspace over the whole window; its terminal is a real xterm.js widget, and the
bridge owns the seated pane through herdr's controller so the PTY has the window's size and herdr's history can be
scrolled. Research: the issue's spikes, `docs/research/wterm-assessment.md`; ground truth for herdr 0.9.1's controller
was measured in throwaway sessions (release, refusal, scroll pinning, frame sizes, widths). Code: `game/src/ui/seat.ts`,
`game/src/laptop/{seatTerm,seatTermLogic,watches,index}.ts`, `internal/herdr/termcontrol.go`,
`internal/server/termcontrol.go`; protocol "The seated terminal (#176)".

| # | Decision | Detail |
|---|---|---|
| 1 | Engine | **xterm.js 6.0.0** (already the monitors' parser), opened in the workspace, with the official **@xterm/addon-fit 0.11.0** (the grid of the area at a fixed font), **@xterm/addon-web-links 0.12.0** (plain URLs, soft-wrapped ones joined) and **@xterm/addon-unicode11 0.9.0** (`activeVersion '11'`: herdr's grid measures emoji and CJK 2 cells, combining marks 1, as Unicode 11 does; xterm's default Unicode 6 would shift columns). No Ghostty or wterm (the user's decision), no webgl, clipboard, search or serialize add-on (DOM renderer; no local history to search or serialize; OSC 52 reads would hand the clipboard to the pane). All MIT. The repo keeps no list of JS package licences (only `FONT_LICENSES.txt`), and the bundle strips their licence comments, as it already did for xterm 6 itself: shipping their MIT notices is left with the other packages' (not part of this change). |
| 2 | Layout | The overview's pattern: `position: fixed; inset: 0`, inside the HUD (so the toasts stay above it), the game behind it inert (the canvas and the HUD's other parts; never a dialog, a toast or a popover such as the limits plate), drawn at the covered rate (`OPAQUE_HZ`), focus restored on standing up, a clip-path grow out of the monitor (an opacity fade with reduced motion; never a transform: it would break xterm's measuring and mouse mapping). The seat bar became it: header (whose laptop, the worker's status tape, Terminal / Conversation / Images as three buttons, the preset and text size, Stand up), a notices line (question, Codex launch, read only), the content area (the terminal; the conversation and the images over it, at its size), the keys. No browser Fullscreen API. The limits plate has no gutter beside it: it steps away (Shift+L peeks). |
| 3 | One keyboard owner | The seat's hidden textarea keeps the focus (IME, paste, copy), inside the workspace, so it is never a dead target. The widget takes no key (`attachCustomKeyEventHandler(() => false)`), its textarea hands the focus back, `disableStdin` is on, `onData` / `onBinary` are never read, and the parser's replies (DA, DSR, DECRQM, DECRQSS, window reports, OSC 4/10/11/12 queries) are swallowed where they start (`swallowReplies`, tested against a real xterm). Keys stay `seatedKey` → lanes → `worker.keys` / `worker.prompt`; paste and its secrets review, image paste and #38's insert-before-Enter are unchanged (a paste landing on the widget goes the same way). |
| 4 | Font and grid | The font size is fixed: the preset's mono × 1.2 × the terminal zoom (A− / A+ / Ctrl + wheel / Ctrl+0 and the preset change it; a window, layout or DPR change never does). `document.fonts.load` before `open()`, `open()` once the workspace shows, a fit on xterm's first render, a `ResizeObserver` and a DPR media query after; the grid (40–300 × 10–100; a smaller area clips) is the watch's `control` grid and then a `terminal.resize` debounced 120 ms. #175 holds: 100% never enlarges a pane's text by itself (an owned pane reflows to the window's columns; a read-only one shows at its own size, and one bigger than the content area scrolls inside it: the wheel, the scrollbars, or the arrow keys once the terminal is tabbed to, a focusable region then; the rest of the keys still type). |
| 5 | Transport | `terminal.watch {control: true}` (no new watch command, so caps, pump, backoff and every end are shared with the observer), `terminal.resize`, `terminal.scroll` (wheel or `bottom`), and two connection-scoped messages: `terminal.control` (who owns the pane) and `terminal.history` (`pane.get`'s offset, read through the read-only socket client, a method added to its allowlist rather than a CLI per poll). One controller per connection. A control watch keeps its process: no restart for a new fps (so the seat stays at its fps while you read), a resync is a same-size resize (herdr answers every resize with a full frame), and a new controller waits for the worker's one being released (else herdr refuses it for its own predecessor). Stdin commands go through a bounded queue, at most 64 KiB each (herdr closes a client at 1 MiB). A full queue (herdr not reading for a moment) drops what the new command makes moot rather than refuse it: a size the sizes before it, the reset to the live bottom the wheels before it; a wheel is refused. The restore size and the release always reach a controller that is still reading: the oldest queued commands make room for them, and a controller that never reads them is stopped after the grace (logged). |
| 6 | Ownership | Never `--takeover`. herdr's refusal (`terminal.closed` "… already has an attached client …", exit 0) or a takeover makes the watch a read-only observer at the pane's own size, for good, said in the workspace ("Another client controls this terminal: it shows at its own size, and the wheel does not scroll it"); typing still reaches the pane (herdr's `send-keys` works while another client owns it). A controller that keeps failing (4 in 30 s) falls back the same way (`failed`). EOF without `terminal.closed` restarts with the observer's backoff. |
| 7 | Release | Every end writes `terminal.release`, gives the process 1 s, then stops and reaps it. Before the release the PTY is resized back to the pane's size before the attach (the session snapshot's): measured on 0.9.1, with no herdr TUI attached the PTY stays at the controller's last size after a release or a SIGTERM; with one, herdr restores the TUI's size itself. A SIGKILLed bridge cannot restore (the kernel kills the controller; herdr drops the lock). |
| 8 | History | Wheel and trackpad over the terminal → `attachCustomWheelEventHandler` (prevented, never xterm's arrow fallback; read only, left to the browser: it pans the pane inside the content area) → whole lines from the summed deltas, at most one `terminal.scroll` per 60 ms; herdr decides between its history and the application's wheel. Output while scrolled up does not move herdr's view and sends no frame, so the bridge reads `pane.get` after a scroll and every second while the offset is above 0; the "N lines up" button goes back to live. Typing returns to live: herdr's `pane send-keys` does not (measured), so every job on the worker's input lane first sends the controller an empty `terminal.input`, herdr's reset. The state (`ControlState.history`: offset, max, rows) is what part 2's scrollbar binds to. `scrollback: 0` and RIS + frame on every full frame: no local or fake history, also after a resync or a reconnect. |
| 9 | Selection, copy, links | Drag selects (xterm's own).
