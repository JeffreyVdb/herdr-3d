# Child agents decisions

## 2026-10-17 — #22 (phase 1 of #20): the native child-agent model and protocol

The provider-neutral record of the subagents a worker's own Claude Code or Codex session runs, its events and how it
survives a restart, with a fake source to build against before the providers land (phases 2, 4 and 6 of #20 are sources;
phase 3 renders it, phase 5 opens a child's transcript). Code: `internal/childagents` (`Registry`, `Source`,
`Evidence`), `internal/childagents/childagentstest` (the fixture source and scripts, test code only),
`internal/server/children.go` and the hooks in `hub.go` (`childSession` on every worker refresh, `Remove` beside the
workers' other per-worker state), `game/src/world/children.ts`, `decodeChild` in `game/src/net/protocol.ts`. Docs:
`protocol.md` "Native child agents (#22)".

| # | Question | Decision |
|---|---|---|
| 1 | Where the generation lives | **On the worker, `child_generation`**, and on every child and `child.removed`. It changes exactly when `agent_session` does, which already sends a `worker.upsert`: the replacement and the new generation arrive in one event, before any child of the new session, and the snapshot carries every worker's generation, also with no children (a client needs it to drop a late one). No `children.reset` event and no `child.removed` per dropped child: the `worker.upsert` is the explicit signal. `syncFloorWorkers` compares workers with `reflect.DeepEqual`, so the generation must not move otherwise; it does not (only `Registry.Worker` sets it, on a session change). The children themselves are never on the worker. |
| 2 | What a generation is | **The next value of one bridge-wide counter**, not a per-worker count: a worker that is removed and comes back (identity matching can keep its id) always gets a higher one, and the bridge keeps nothing of removed workers. Compare per worker only. A bump is a non-empty `agent_session` that changes, to another or to none; a first session after none (`""` → X) keeps the generation, since evidence of an unbound session never attaches. Herdr losing a session for a moment drops the children; they come back with the replay when it returns (row 5). The counter restarts with the process, which the epoch change covers. |
| 3 | How the bridge drops an older generation's evidence | **Evidence names the root agent session, never a worker or a generation.** Sources know sessions (Claude's `session_id`, Codex's root thread); the registry binds each worker to its current session and resolves evidence through that binding, so evidence of a replaced session finds no worker and is dropped (`ErrUnbound`), whatever the source thought the generation was. A session another worker already holds is not bound twice (its evidence stays with the first). Phase 4 can bind the session the usage tracker finds for a Codex worker herdr knows none of through the same `Registry.Worker`. |
| 4 | Provisional ids | A row's id is `ch_` + 16 hex of sha256(worker, generation, provider, the first id seen and whether it was the native or the dispatch id). The root indexes both ids (`native`, `dispatch`, provider-scoped); evidence with both links them, so the provisional row gains `native_id` and keeps its id; evidence by either finds it. A dispatch that already has another native id is a conflict and dropped. Two rows that turn out to be one child (a native-only hook before the link) merge into the one seen first, with a `child.removed` for the other: the only removal reconciliation makes, and unavoidable without guessing a pairing by time. The row that stays keeps every field either row observed, never older evidence over newer: each row remembers when evidence last set each last-wins field (the root's observation count, so a replay gives the same answer), and a merge takes the later one (`state` with its `source`, `ended_at` also when a resumed `running` cleared it, `name`, `type`, `description`, `transcript`); the earliest `started_at`, the latest `last_activity_at`. Not by `last_activity_at`: a row often has none, and evidence that sets a field need not move it. Deterministic ids make the same evidence give the same rows (the frames fixtures are stable), but the graph's identity is the tree, not the ids: the rebuild tests compare trees. |
| 5 | Persistence | **None.** The children's truth is the providers' evidence (transcripts on disk, the server's threads), and a stored graph would be stale after a restart (a process lost, a child finished meanwhile). The `Source` contract is a replay: whenever the hub binds a worker to a session it has not bound (every worker after a restart, a new or first session), it calls `Replay(session)`, and the source sends everything it can find for it again, in observation order, through `Run`'s emit. `Replay` never blocks (the hub calls it on its goroutine); `emit` returns once the hub applied the evidence. Tested by a fresh registry fed by replays only, and by a restarted hub on the same database with the source's evidence (the same trees) and with an empty source (no children). |
| 6 | Unknown is a value | A new child is `state: unknown`, `parent: unresolved`, `transcript: unavailable` until evidence says otherwise; a state outside the list is read as `unknown` (dropping the evidence would lose its other fields). Evidence fields merge: a set field replaces, an empty one keeps; `started_at` keeps the earliest, `last_activity_at` the latest; `running` without an end clears `ended_at` (a resumed child). The registry has no clock and no timeout, so quiet logs never complete anything. |
| 7 | Parents | Evidence names a parent by its native or dispatch id. One not seen yet leaves the child `unresolved` and remembers the name; the parent showing up resolves it in the same observation (the parent's upsert first). A removed parent leaves its children `unresolved`, waiting for it. A parent that would make a cycle is ignored, also through a merge (row 4): the row kept takes the parent of the two rows observed later if it is still one (not the row itself, which a parent naming the other row would be, nor a descendant of either), else the other's, else `unresolved`, and the dropped row's children go under it through the same check (`link`), `unresolved` should one make a cycle. `childTree` (and `childagentstest.Tree`) show a row whose parent chain comes back to it under the root worker anyway, so a bad parent can never hide a row and its descendants. Evidence cannot say "unresolved" (Kind is `root` or `child`): not naming a parent leaves it as it is. |
| 8 | The fake source | `FixtureSource` (`Emit`, `Replay`, `Wait`) is driven step by step by the tests, never by a timer, so the frames are deterministic: a session change is the test publishing herdr's observation and waiting for its `worker.upsert`, and `Wait` covers the replays it asked for. Scripts (`internal/childagents/testdata`) say what happens and the trees each worker must end with; the same files drive the registry tests, the hub test and Vitest (via the frames). |
| 9 | A dev way to see it | **The game's fixture bridge plays the frames** (`?ws=/fixture/children-<name>`) instead of a hidden `herdr-world` flag: the fixture's sessions could never match a real bridge's workers, and the recorded frames are what a bridge sends, with no production path. |
| 10 | Limits | 500 children per root session (evidence of a new one beyond is dropped, `ErrFull`); `name` and `type` at most 128 bytes, `description` 1000, cut on a rune boundary. |

## 2026-10-17 — #23 (phase 2 of #20): Claude Code subagents from their transcripts and the bridge's hooks

The first production source of #22's model: a Claude worker's subagents, from its own session's files and, for the
Claude workers the bridge starts, its own observational hooks, on **Claude Code 2.1.302**. Code: `internal/claudechild`
(`Source`, `Listener`, the facts and their derivation in `book.go`, the hook settings in `hooks.go`), the
`usage.Children` listener in `internal/usage/session.go`, `UsageConfig.ClaudeChildren` in `internal/server/usage.go`,
the `--settings` launch shapes in `internal/herdr` and the wiring in `internal/app` (`-claude-hooks`). Research:
`docs/research/claude-subagents.md`. Docs: `protocol.md` "Claude Code subagents (#23)".

| # | Question | Decision |
|---|---|---|
| 1 | Who reads the files | **The usage tracker's `usage.Session`, once per file**: it already tailed the main transcript and every `subagents/agent-*.jsonl` (its usage counted them), so a `usage.Children` listener beside `Lines` and `Tap` gets the main lines, each child's lines and (new) each child's meta file when it changed (stat per poll, read whole when its identity, size or time moved: Claude renames a new one over it), `Gone` when a file goes, `Reset` when everything is read again, `Polled` at the end of a poll. The listener asks for an early listing (`WantList`) while a call's file is not seen, so a child does not wait for the 10 s `SubagentRescan`. The source owns only the hook log's tail. |
| 2 | How evidence is made | **Facts keyed by explicit ids, derived anew after each poll.** Each reader keeps the session's facts (calls by `tool_use` id with the transcript that holds them, results, notifications, metas, files with their first, last and latest-prompt timestamps); the hooks' facts are kept apart. After a poll the children are derived from all of them and only what changed is sent (and a `Removed` for a child sent that is gone); a line read twice, a reset or a restart gives the same answer. Not per-line deltas: an end and a resume read in either order must give the same state, and the replay must send the latest word. |
| 3 | Pairing | **By ids only**: a meta's `toolUseId`, a call's result naming its `agentId`, a notification naming both, a `PostToolUse` hook; the first pairing of an id wins (that order), a later one naming another partner is ignored. Never by launch order, mtime or `promptId` (shared by concurrent siblings). A child file whose pairing is not there yet is held up to 5 s (`HoldUnpaired`, bridge clock) while a call of the session is unpaired, so the child shows as the provisional row gaining its native id instead of a second row merged into it a poll later (#22's merge, which removes a row); after that it shows alone. |
| 4 | Parents | **The transcript holding the call** (the root's: `root`; a child's: that child), else the meta's `parentAgentId`, else a meta's `spawnDepth: 1` (`root`), else none: `unresolved`. A depth-2 child is in the same flat `subagents/` directory; its parent is never guessed from depth or timing. |
| 5 | Lifecycle | **The transcripts decide it; the latest end wins; a later prompt resumes.** Ends: the call's result (`completed`; `is_error`: `interrupted`), a task notification (`completed`; `killed`/`failed`: `interrupted`, phase 1 having no failed state), the meta's `finished` at the meta's write time. A user record that sets the child to work after the end (a prompt; a meta record with an `origin`: a SendMessage, `coordinator`, or its own background task, `task-notification`) makes it `running` again with `ended_at` cleared; the interruption marker `[Request interrupted …]`, a tool result or a meta record without origin does not (the interrupt case writes the marker 3 ms after the parent's rejection). Nothing times out; a root's turn, `Stop` or exit ends no child. |
| 6 | Hooks | **Observational, optional, one shared log.** `--settings <dir>/settings.json` (one flag, merged by Claude with the user's and the project's hooks, which are never touched) installs synchronous command hooks on `PreToolUse`/`PostToolUse` (`Agent|Task`), `SubagentStart`, `SubagentStop`: `flock -w 2 LOG cat >> LOG 2>> LOG.err || true` (whole lines under concurrency; any failure ignored). One log for every worker, routed by `session_id` (a per-session file cannot be named before the session exists); rotated past 8 MiB with one older file kept and read again after a restart (lines appended to the old file in the instant of the rotation can be lost: the transcripts have them). Hook input has no timestamp, so hooks never decide a lifecycle: they add the call before its transcript line, the pairing, the nested parent (`agent_id` on a nested `PostToolUse`) and the type. A `SubagentStop` is never an end (a Stop hook can keep the child working). No `Stop` hook: `background_tasks` would add nothing the transcripts lack. |
| 7 | Launch | Two new allowlisted shapes, `start-claude-settings` and `resume-claude-settings` (`TestControlAllowlist`), used when `Control.ClaudeSettings` is set; the file must be a plain absolute `.json` path (`validSettingsFile`), which single quotes hold in any shell for the typed resume. herdr's own resume of a woken Claude does not pass it: those sessions are read from their transcripts only. Without `flock` or a writable directory the bridge logs a warning and runs without hooks. |
| 8 | Not children | A teammate (`team_name` on the call, `teammate_id` on its result; docs only) and an internal helper (hooks with an empty `agent_type` and no call or file: 15 of them in the smoke session) make no row; a child file whose first records name another session or agent is ignored, everything in it (a call, a result, a notification: review round 1), also what it showed before a record named the other one (retracted: review round 2), but a call it shares with another transcript stays that one's, with its result there, whichever was read first (each transcript's copy of a call is kept: review round 3). A fork is a child; the copied call at its file's start (after `fork-context-ref`) is skipped, and a call already known is never re-homed. |
| 9 | Replay | After a restart the source knows nothing; the tracker reads every worker's files from their start, which sends everything once the hub bound the worker. `Replay(session)` sends what the session's facts give now (a session bound again while it is read: a worker that let it go to another). Two workers claiming one session: the first reader's facts are the session's, the next one's take over when it closes. |
| 10 | Fixtures | Real 2.1.302 recordings (`internal/claudechild/testdata`, cases a–g2 of the research), rebuilt from the throwaway sessions' files in Claude's compact JSON with the parser's fields untouched, thinking, long text and attachment payloads cut, and names scrubbed. The research's first fixtures had cut long strings, notifications' `<status>` included; they were not used. |

## 2026-10-18 — #25 (phase 4 of #20): Codex subagents from rollout files (terminal path)

The second production source of #22's model: a Codex worker's subagents on the terminal path (not the shared app-server:
#27), from its session's rollout files, on **codex-cli 0.160.1, 0.162.1 and 0.163.0**. Code: `internal/codexchild`
(`Source`, `Listener`, the facts and their derivation in `book.go`, `Rollout` and `ReadTranscript`), `codex.Meta`,
`codex.ParseMeta`/`ReadMeta` and `codex.ChildFinder` in `internal/codex/sessions.go`, the Codex branch of
`usage.Session` (`readChildren`), `UsageConfig.CodexChildren` in `internal/server/usage.go`,
`transcript.CodexHistoryStart`, and the wiring in `internal/app` (with `-codex-sessions`). Research:
`docs/research/codex-subagents.md`. Docs: `protocol.md` "Codex subagents (#25)".

| # | Question | Decision |
|---|---|---|
| 1 | Who reads the files | **The usage tracker's `usage.Session`, once per file**, as for Claude: it already tailed each Codex worker's root rollout, so its `usage.Children` listener gets those lines; with a listener set it now also finds the session's **child rollouts** (`codex.ChildFinder`: the date directories from the root rollout's day on, newest first, at most `MaxScan` files; a child by its first line only, `thread_spawn` with `session_id` = the root; first lines read whole are remembered, one still being written is read again) every `SubagentRescan` or when the listener asks (`WantList`: a spawn within a minute whose rollout is not read), tails them and sends their lines by thread id. Not the `Finder`'s metas: they are the root lookup's, keyed for cwd, and only exist for workers herdr reports no session of. Not a second tail: no other reader of the child files exists, and the root's is shared. The child files' tokens are **not** added to the worker's usage (the root's reading is unchanged; Codex root behaviour stays as it was). |
| 2 | How evidence is made | **Facts per file, keyed by explicit ids, derived anew after each poll** (#23's rule): each rollout's facts (its first line, its spawn calls by `call_id`, the threads its activity records name, lifecycle observations keyed by turn id or activity id) are kept by that file; the children are derived from all of them and only what changed is sent (a `Removed` for one sent that is gone). A file that goes or turns out not to be this session's takes everything it showed with it (#23's retraction, by construction). Every piece of evidence carries the thread id, so a row's id is its native id's from the first observation on: no provisional rows, no merges; `DispatchID` rides along when known. |
